Redesigning an on-site inspection reporting platform for field workers who rely on tablets and mobile phones — not desktops.

Overview

This platform allows inspection personnel to report results on-site and tracks abnormal situations. It runs as both a web app and a native mobile app, with the web version additionally supporting desktop and tablet screen sizes.

The platform was already in operation when we joined. The scope was UX and visual design optimization — not a rebuild — which meant working within existing information architecture while improving usability for real-world field conditions.

The Problem

The original interface was built for desktops, with fixed-width tables that didn't adapt to different screen sizes. In practice, field staff used vertical tablets and mobile phones on-site — meaning they constantly scrolled horizontally just to read basic information.

Goals
01

Eliminate horizontal scrolling for field staff using vertical tablets and phones

02

Adapt the information display to different screen sizes without losing data density

03

Leverage native mobile interaction patterns to reduce friction for less tech-savvy users

04

Minimize resistance from existing users by preserving familiar workflows where possible

Research & Context

Because the platform was already live, user interviews revealed a key constraint: existing users had built mental models around the current flow. Major structural changes would face pushback. This shaped the optimization strategy — improve without disrupting.

Key Observation

Many users didn't know table headers could be clicked to sort. For a user group less familiar with digital products, affordances need to be more explicit — subtle conventions aren't enough.

This insight extended to how I approached the entire redesign: less reliance on assumed digital literacy, more reliance on visible cues and familiar mobile patterns.

Key Design Decisions
Column layout with wrapping instead of fixed-width table
To avoid horizontal scrolling while preserving all information, table columns were redesigned to wrap overflow content. This maintained the familiar table structure while adapting to narrow screens.
Info cards for vertical tablet view
For the vertical tablet interface, I replaced the table with info cards. Though it sacrifices quick column-scanning, it eliminates horizontal scroll entirely. Detailed filters compensate for the loss of quick comparison browsing.
Native mobile gestures throughout the app
Implementing common mobile conventions (long-press to select, tap blank area to dismiss) reduced the number of explicit UI buttons needed and made the app feel less foreign to users more comfortable with consumer apps than enterprise software.
Final Design
Final screens — covered under NDA

The design that resonated most with users was the login screen. Using shapes and lines derived from the project's own visual language, paired with a stable, minimal color palette, it struck a balance between "designed" and "professional" — and became the visual reference point for the client's future product series.

Results & Impact

★

Takeaways
①

Tablet-first is genuinely different from mobile-first. The interaction model, screen real estate, and usage context all differ enough to warrant separate design thinking — not just breakpoint adjustments.

②

Designing for users less familiar with digital products demands more explicit affordances. Subtlety is a design luxury that not all user groups can afford — clickable elements need to look clickable.

③

Optimizing an existing system requires political as much as design skill. Preserving familiar flows while improving them — rather than replacing them — made the improvements far more adoptable.
