Overview

This proposal outlines a central monitoring system that integrates observation and alerting capabilities across multiple IoT data sources. It enables customization of alert event types and triggers notifications via email, SMS, or other channels to designated response personnel. The system aims to achieve early detection and rapid resolution of hazardous events.

My work covered the full design scope: information architecture (front-end and back-end sitemaps), wireflows, UI system design, and high-fidelity prototypes for stakeholder presentation.

The Problem

Without a unified monitoring platform, operations teams had to check multiple disconnected systems to track IoT events — increasing response time and the risk of missing critical alerts. The client needed a single interface that could surface, prioritize, and route hazardous events to the right personnel automatically.

Research & Architecture

Based on the client's requirements, I designed sitemaps for both the front-end and back-end — ensuring all features and content were captured in the development plan before wireframing began.

Architecture Decision

A centralized information page with drill-down detail views — rather than separate pages per source — let operators get an instant overview before investigating specifics. This reduced the number of navigation decisions needed during a time-sensitive alert.

The architecture included a contact management feature and hardware considerations for the command center environment — anticipating operational constraints beyond the screen.

Key Design Decisions
Transparency and background blur for the tech-forward aesthetic
Translucent panels layered over data visualizations reinforce the sense of a live, real-time system — more "command center" than standard enterprise software. It also lets dense data remain visible through UI layers without feeling cluttered.
Gradient encoding for value strength and category
Color gradients were used not just decoratively but informationally — representing signal strength, severity, or category ranges. This let operators read state at a glance without reading individual values.
Local design variables for consistent theming across the system
With a large number of screens across multiple roles and contexts, a local variable system in Figma kept colors, spacing, and component states consistent and easy to update globally — and gave the engineering team a clear token reference for implementation.

Organizing and structuring the large volume of information across roles and screens was the core design challenge of this project. Extensive table filtering options were designed and validated through research to ensure usability without overwhelming less-technical operators.

Takeaways
①

Large-volume information design is primarily an architecture problem. Before any UI detail, the structure of what goes where — and how users move between contexts — determines whether the system is usable.

②

Designing for multiple screen sizes from the start forces clearer information hierarchy. If the content structure can't survive a smaller screen, it usually means the structure isn't solid enough even on desktop.

③

Extensive filtering for data-heavy interfaces is non-negotiable. The key is designing filters that feel intuitive — through careful labeling, logical grouping, and visible filter state — not just adding more options.
