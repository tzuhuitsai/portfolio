Overview

Georifters is a console puzzle game for up to 4 players, with single, team-up, and battle modes. It was developed by Playerium and published across Steam, Nintendo Switch, PS4, and Xbox.

As part of the 2D design team, my responsibilities spanned lighting, environment concept, UI/UX design, and video editing. The 2D team started from UI design first, then gradually joined the UX design process — working within a prototype that resembled a sitemap rather than starting from user research.

The Problem

Console UI presents a distinct set of constraints: players navigate with a limited number of controller buttons, every interaction must feel responsive and readable at TV distance, and the system needs to accommodate future DLC and updates without a full redesign.

Goals
01

Use visual elements from the 80s to establish a consistent, memorable aesthetic

02

Control UI performance — keeping animations smooth without sacrificing visual richness

03

Preserve extensibility for future updates and DLC without requiring structural redesigns

Research & Exploration

The design process began with art style exploration — we needed to define a visual direction that was achievable within the team's production capacity and timeline. After evaluating options, we selected a 2D comic style for its balance of expressiveness and production efficiency.

Style exploration

Design Constraint

Controller navigation has far fewer input options than keyboard/mouse. Every screen had to work with directional input, a confirm button, and a back button — making clear focus states and minimal action depth non-negotiable.

Beyond internal testing, the company arranged external usability studies. Participants filled out questionnaires covering overall experience, operation difficulty, and UI/UX feedback — all tracked in JIRA for the team to review and prioritize.

Key Design Decisions

Design system

Once the art style was established, we standardized the typeface, color palette, and material treatment across all UI elements.

2D comic style for the UI art direction
Compared to full 3D or realistic rendering, 2D comic style offered faster production cycles and consistent readability at all screen sizes — critical for a team balancing game development and UI simultaneously.
Techboard specs for engineer communication
Instead of just exporting screens, we delivered Techboards — layout sheets with explicit size specifications and annotated animation targets. This eliminated ambiguity and reduced implementation back-and-forth significantly.
Character ability info accessible via Y button on character select
Usability studies revealed players wanted to review character abilities during selection. Adding a dedicated Y button shortcut — with a clear on-screen prompt — gave players the information they needed without cluttering the main selection interface.

Takeaways
①

Console game UI has constraints that don't exist in web or app design — controller buttons, TV viewing distance, and frame-rate performance are all design constraints, not just engineering ones.

②

Working across disciplines (UI, concept art, lighting, video) over 22 months gave me deep respect for how every element of a game contributes to the player's experience — and how design decisions ripple across teams.

③

Overcoming real constraints — limited inputs, strict performance budgets, future-proofing requirements — is where the most interesting design thinking happens. Restrictions focus creativity rather than limit it.
